## 技术判断需要遵守的四条边界

1. **“可读懂”不等于“可导入”。** 静态字段解释有风险；正式采用需要官方编辑器导入、预览、控制信号和当前版本官方 API 的核对。
2. **“2D 画风”≠“客户端图片控件”。** 部分像素造型其实是 3D 世界中大量装饰物或场景实体。统计并单独验证场景实体、UI 控件、动画驱动与缓存生命周期。
3. **“一个文件几十 KB”不等于低负载。** 区分打包字节数、官方容量、初始化写入、绘制实例和运行中的帧时/内存；人眼画质必须逐屏过审。
4. **仅参考思路。** 项目公开 PR 不托管社区完整 GIA/GIL、解包图、第三方角色代码、私有 Drive 文件 ID；官方资产和作者素材分别遵守平台与独立权利，最终美术重做或取得明确许可。

## 用到的已知平台能力

- [原生图片控件](https://act.mihoyo.com/ys/ugc/tutorial/detail/mh2oih9jou22)：遮罩、填充、羽化、图片 ID、颜色、层级。
- [原生预设按钮](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhdbkf04v6y8)：普通、悬停、按下、不可用四态。
- [客户端控件 Lua API](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhtakr07vej4)：Tween/Sequence、容器变换、控件实例、输入与手柄焦点。
- [MCP 官方文档索引](https://github.com/FurinyaWorks/genshin-miliastra-mcp)：先核 API、模板及当前版本能力。不得将工具自设限值误作所有平台的硬限制。

> 对正式竖切真正有用的优先顺序：**(1) 启动/选角高成本源头 → (2) 原生 UI 皮肤/状态 → (3) 小型角色和攻击/受击/死亡 → (4) 手牌 Tween 对照 → (5) 全生命周期 Android 复测**。其他样本先不开发。
