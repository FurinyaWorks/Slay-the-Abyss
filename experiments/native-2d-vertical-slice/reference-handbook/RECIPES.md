# 技术精髓与精确读取位置

以下路径均相对私有资料包的 `extracted/`；行号针对 CATALOG 固定字节版本，换文件后应重新提取。每项明确区分**样本事实**与**对本项目的建议**，不是宣称已在本项目接入。

## 1. 高质感按钮、卡框：学分层，不是继续堆像素

**读原件**：`jelly-ui/main/0000.json.gz` 为“开始界面按键”，0002 为“圆边按键”，0003/0004 为钝角/方角。根记录在 `root.1[n].19[0].1[0]`；`index.json.ui` 可按 parent/id 还原依赖层级。第一套有22个依赖，并非每个按钮需要整个包539个子控件。`dragon-dialogue/main/0000.json.gz` 及全部184个依赖是完整对话框底板。

**字段定位**：UI原始记录501是身份，504是父引用，503是打包子ID；505为组件列表，其502标识组件类别。不要按名字合并同名“图片”，使用ID/父子链。果冻的客户端图片分量出现96/97，常规图片包出现38；相同画面不代表相同序列化格式。

**迁移建议**：按 V25 一套按钮拆成外轮廓/底板/高光/内容/命中区，优先复用能表达该形状的官方图片与伸缩模式；装饰不拦截输入，文字保留动态数据。四态分别核对，触屏取消/拖出必须复位。先重建一个真正点击现有 Run 命令的组件，再推广共享模板。转场只推动父级或少量属性；不要求每个控件时时动画。

**不要误学**：“受龙所选”本身182张图片，不应在10张牌上照搬。已有 flat-card 省控件不等于 V25 皮肤达标。不能因模板名称含“按钮”，就假定已有脚本、四态回调和手机命中。

**项目入口**：`scripts/native-ui-theme.mjs`、`scripts/game-ui-layout.mjs`、`scripts/card-face.mjs`、`src/lua/abyss_card_skin.lua`、`data/presentation/ui_theme.json`。对每个原件字段记录“保留/重映射/不支持”，不得静默扁平化遮罩后再宣称等效。

## 2. 原创角色：区分低负载 UI 包和客户端像素脚本

**低负载UI精确入口**：`lowload-characters/main/0102.json.gz` 是“荧Lumine”（42依赖），0093是雷电将军（43依赖），0066是芙宁娜（43依赖）。包内124根+5350子记录；先用根ID沿依赖/父子关系查到单个角色，不加载全包。

**兼容性修正**：这个包的根 `recordType=61`，常规组件类型含56/23，图片为38；果冻客户端根 `recordType=70`，组件含86/83，图片分量96/97。**不能把两者均称为可直接交给 InstantiateClientUIControl 的模板。** 可读取其几何、配色、分层与图元ID，映射到客户端模板；或者按原来常规UI/节点图路径使用，二者分别验证。静态差异是已见事实，具体引擎类名/转换正确性仍须官方读回确认。

**客户端Lua精确入口**（pixel-scripts）：

| 角色 | 文件 | 主要函数行号 |
|---|---|---|
| 荧 | `scripts/092-1073741917.lua` | ReleaseControls184、DrawRect194、BuildImage217、OnStart247、OnDestroy264 |
| 雷电将军 | `scripts/120-1073741945.lua` | ReleaseControls154、DrawRect164、BuildImage187、OnStart217、OnDestroy234 |
| 芙宁娜 | `scripts/088-1073741913.lua` | ReleaseControls220、DrawRect230、BuildImage253、OnStart283、OnDestroy300 |

**机制**：静态 DRAWS 矩形数据+PALETTE，64×64逻辑格，统一缩放，创建时设置颜色/位置；生命周期状态防止重复创建，异常时释放，销毁倒序回收。荧的模板索引初始为0（第6行），必须换成目标存档实际创建的模板ID，不能硬抄源ID。图元 `100001` 是素材ID，与模板ID不是同一概念。

**迁移建议**：保留数据与运行时分离；每个战斗实例独占宿主和生命周期，外观数据可以共享，动画推动少数父组；只创建当前屏需要的人物。V25要求的人脸/身形不能被随意降为低细节像素，是否采用此风格须同状态对照。雷电资料用作技术样本，不因此开放首发职业。

**项目入口**：`scripts/official-portraits.mjs`、`scripts/art/lightweight-2d-assets.mjs`、`src/lua/abyss_traveler_portraits.lua`。不要直接用参考脚本按全画布尺寸布局；改接当前角色宿主、安全区和既有命中框。

## 3. 象棋/2048：输入事务与原生补间生命周期

`xiangqi` 内有两份脚本，勿读错：
- `scripts/001-1073741827.lua`（testXiangQiProject）：PlayTweensParallel203–236、KillAllAnims238–245、CreateRect345–359、CreateRoundRect361–363、CreateCircleShapes365–403、AnimateMove1735–1782、HandleTap1784–1809、OnDestroy1994–2011。
- `scripts/000-1073741826.lua`（test2048Project）：trackTween145、tweenGroup160、killAllTweens186、playMoveAnim452、handleMove513、enqueueMove606、OnDestroy738。

**机制**：先挂完成监听，再统一Play；计数汇合全部完成，仅正常完成触发后续；取消登记并Kill(false)，避免取消被当正常完成；输入检查 busy/当前回合，合法命令和视觉过渡分开。圆形优先一张原生图，无素材时才退为切片。

**移植要改的地方**：象棋仍逐个推动棋子形状和文字，不是天然的最少调用；我们的卡牌应尽量移动已有父容器，并同步真实命中位置。再补本项目的牌UID、battle/turn身份、generation/owner、防双击和迟到回调拒绝，不能把示例当完整的交易防护。

**项目入口**：`abyss_battle_card_view.lua`、`abyss_feedback.lua`及原手势模块；原 lerpSnap 是工作基线，不因“原生”二字强换。比较同曲线、同持续时间、同对象的A/B，验证中断、换页、拖出、失败恢复和完整输入。#553已归档的单轴Tween样例可恢复研究，不直接套旧整体源码覆盖develop。

## 4. 奥黛塔：值得学的分组运动，必须避开的每像素动画

`audetta-idle/scripts/000-1073741825.lua`：classify1100、pingpong1129、build_elements1159、collect_existing1195、start_perblock1222、setup1316、OnStart1374、OnDestroy1395。

**机制**：用坐标划分手臂/头发/头/躯干/裙摆；按关节点计算小角度位移，用重叠消除裂缝；完成回调串接往返Tween，保存停止句柄，销毁先关running再停链并恢复尺寸/清理。

**反例**：848块图元逐块建X/Y链，不宜复制到多敌战斗。建议离线分组、少数父组驱动，保留接缝和遮挡检查；一条链终止后不得被迟到回调复活。此样本只有待机，不等于攻击/受击/死亡。

**此次实际读到**：切换图包含“当前动作”以及“待机/开心/斜眼/伤心”；播放图含“当前动作序列”“展示动作”“做动作”；多实例版增加主物体GUID、上/下空物体GUID、关卡实体GUID与上(10)/下(20)。由此可以研究按实例隔离状态与帧组选择。

**不得夸大**：这不是已具备攻击/受击/死亡的通用战斗动画器；“两组1–20”不能自动解释为只驻留一帧或低成本图集。读原字段、节点类型目录及实际调用后，确认到底切实体状态/显隐/资源，再判断驻留和更新成本。未解码的操作码明确标记未知，不以节点数量假装已理解所有连线。

**建议落地**：从现有Lua战斗事件映射到一套自己的 idle/attack/hit/death 展示状态，规则仍唯一结算；每个对象有owner与动作序号，cancel/换战斗/销毁后拒绝旧回执。先一玩家两敌，随后验证10卡、多段伤害和连续切场。若场景节点路线妨碍2D界面，则移植“状态/帧组/实例隔离”原理，不必搬其世界实体系统。

## 6. Bad Apple：池化、差分、时间预算；不要跳过战斗事件

`badapple/scripts/000-1073741826.lua`：Codec.new313、Decoder:step347、RectParser.new377、Reader:step451、advanceClock578、resolveFrame590、commitFrame599、startDecode631、createRectangle711、drawFrame725、decodeStep752、OnUpdate777、OnDestroy813。

**机制**：素材在离线预编码；运行时分步解码，按池槽懒创建；缓存位置/大小/显隐，只提交变化；播放时钟与解码状态分离，落后时选目标帧而非无限补播；退出停update，解除监听，再倒序销毁池及其他拥有资源。巨大内嵌字符串是数据，不应整段送入LLM上下文，先读函数索引及上述行段。

**适用本项目**：背景块、短特效、数字飘字采用有上限的池；阶段结束收回借用、边界重建时校验实例身份；仅改变的文字/颜色/几何提交。视频跳帧只可用于非关键视觉；**不能跳过出牌、伤害、领奖等语义事件**。4612矩形上限是样例参数，不是平台安全预算；不能据此保证30FPS。

## 7. 文本、页签和教程：普通控件与客户端层分开

`ui-kit`、`tutorial`、`rpg` 原件索引按名称选页签、单选视窗、文本、按钮和信号，不是逐帧重画整页。RPG未见已检查脚本槽中的Lua，不能据此说“没有逻辑”：其行为在节点图/组件侧。

保留本项目原生文本与数据，不把中文转图元。长文案、自动字号、换行、裁切、滚动、手柄焦点、手机点击区域必须一起验收。标题/正文只在内容或布局变化时更新，界面关闭不丢失应保留的当前项。对服务端页签事件与本地Lua状态建立薄适配，不引入第二套Run状态。

`nodePanel/choicePanel` 停用已在#558引入；只是SetVisible不等于停止所有工作。扩大SetActive范围前检查脚本/计时/回执的宿主，不能停根更新后伪造不卡。重复打开、失败恢复和监听器释放属于同一验收。

## 8. 背景、静态造型、卡牌纹样：外形相似不等于同一渲染技术

`lumine`、`slimes`、`mages-hilichurls`、`characters-117`、`sand-and-puppet` 是世界元件/装饰物路线；不要和低负载客户端UI统计合并。`furina-summons`是空模型+装饰部件造型，不是可导入任意mesh/骨骼的证明。

`witch-parkour`、`mondstadt`、`buildings` 可学构图、模块重复、远中近层次和相机，但全城/跑酷实体规模不能作为静态战斗背景的低负载证据。`heart`、`spade`、`sky-frame` 同样是场景装饰，不是可直接设置到ImageControl的单张卡面纹理。

对V25背景：先按画面作用划分远景/主体/前景/动态层，列能用原生纹理、可伸缩图形或少数片块表达的部分；只改变真正动态的层。保持主体轮廓、光色与留白，再测首次可交互、可见资源优先级、热切换与缓存上限。未经证实，不采用“任意PNG转贴图”或“整幅截图拆几千矩形”的默认方案。

## 9. 鼠标实体、镜头、技能：后备能力，非UI必须重写

`mouse-pick`索引含鼠标检测体、射线与选中信号链；`camera-v2`含触发/定时/镜头反馈；`sword`含多阶段技能特效。可研究事件编排、准确目标与取消，但世界射线不等于HUD拖牌命中，也不能保证触屏等效。

2D当前手势已具备事务与取消逻辑，不为复用世界射线而重写。3D若被选择为后备，才完整核对摄像机、实体GUID、原生AI/伤害隔离和清理；静态模型/菜单示例不能认证这些能力。

## 10. 移植方法与验收统一

对每项采用技术记录：原件ID+hash→具体记录/函数→复用原理→许可证/授权→本项目入口→最小负控和正常路径→官方当前候选结果。目标是减少AI猜测，不是把新资料再写成泛泛概念。

原始字段树包含“possibleMessage/floatInterpretation”等研究标签，不能当官方完整schema。使用本机已安装MCP的实际工具描述，优先复用已验证的读写入口；如果MCP构建器限制了平台真实支持的层级/字段，做小范围原件读写回环，别把工具限制当引擎限制。所有ID在目标存档重新读回，所有运行时效果与资源数在同候选验证。
