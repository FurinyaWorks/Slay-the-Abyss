## 这次弥补的交接缺口

旧 #557 是方向和样本统计，没有原文件校验、具体函数或记录定位；#558 因而主要自行生成了低图元角色/背景。现在补齐：28 文件完整 SHA256、128 份 Lua 的逐字节提取与函数索引、GIA 主记录/依赖和 UI 父子身份、节点图字段位置、私有取件方式，以及每种技术的采用/改造/不采用依据。

**覆盖标准是每份样本都有去向，不是把所有技术一起塞进游戏。** Agent 应按 CATALOG 的 28 个 ID 填 `采用 / 改造采用 / 不适用 / 待核`，每项附原件 hash、读到的记录/函数和原因。不要再只写“参考果冻 UI”“用了像素技术”。

## 视觉合同：V25 不是当前 Enhanced 的别名

统一基线已把 #558 的减量方案纳入 Enhanced，但最新版私有 V25 UI 没有被自动移植；经典模式也不是已逐像素验收的 v1.0.0。先从本机保全的私有工作树/bundle 恢复真实设计，冻结版本和截图，再做原生重建。

- 保留 V25 的布局、层次、配色、文字可读性、卡框形状、按钮状态、主要角色辨识与动效节奏。
- 不得用 27/57 图元的临时人物、单片矩形卡框或任意低模背景代替 V25，然后宣布“性能达标”。
- “每角色不超过 60 控件”只是旧实验参数，**不是设计验收要求或官方限制**。预算由真实设备与画质对照共同决定。
- CSS 模糊、复杂纹理、自定义字体等不能假定可原样映射；逐项记原生等效实现与可见差异。未经 Owner 确认不偷偷降级。
- “不能公开第三方素材”不等于“不能研究原件或使用获得许可的实现”。先核许可，能合法复用就复用；否则保留原理、独立实现，禁止无理由重新发明整套框架。

## 本轮实际核验边界

重新检查了 28 个 GIA/GIL 原件的包装长度/版本/尾部、SHA256、主记录/依赖/脚本字段；128 份提取 Lua 与原文件指定字节范围逐份相等。私有只读提取器的 8 项测试覆盖截断/非法头、字段、精确脚本、路径名称隔离、禁止覆盖及不执行样本代码。两份红心原件已逐字节确认一致。

原生编辑器导入、当前画面、攻击动作、持续帧率、手机、容量、完整流程**不在这些静态核验之内**。未取得 V25 私有原件的本机可视验收，本交接不能代替它。

新发现尤其不能遗漏：低负载角色包的常规 UI 字段（38/56/23）与果冻客户端 UI 字段（96/97/86 等）不同；动态可莉已见“待机/开心/斜眼/伤心”，不是现成战斗动作包；象棋存档另含一份 2048 脚本。详见 RECIPES。

## 路线决策不再随口摇摆

2D 同时满足 V25 视觉、交互及目标设备全生命周期指标：继续 2D，并完成两幕自然游玩。若确认为平台表达/性能硬瓶颈，在保留失败证据后停止无界 2D 尝试，恢复归档 3D 做同标准替代。**缺文件、缺设备、权限不足是阻塞，不是 2D 技术失败；3D 也不自动免除 V25 风格与实测验收。**
