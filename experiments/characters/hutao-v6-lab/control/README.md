1. 恢复/冻结完整75卡、150基升、遗物、规则与可玩入口，确定用户实际试玩版本，比较聊天版与PR640差异。保留旧版A，不改写历史。
2. 从代码和交互复现症状，分别验证可打性、条件收益、启动成本、抽牌时序、付血/回血/敌伤和界面暗示；不要预设“半血锁”是唯一根因。
3. 预登记指标、策略、训练与留出种子、实验预算。比较现状A和最少一个候选B；小卡池用于筛掉坏机制，不代替最终完整75卡。
4. 同一规则驱动UI、文案、离线测试；先小样、反例、修正，再扩回完整75卡+遗物。维持人物辨识度，不把限制全删成超模，也不凭角色主题为坏体验辩护。
5. 冻结候选manifest（源码身份、卡表、遗物、规则、测试、原始结果、已知问题），三方分别审查；保存每个发现及修复回执。争议靠反例和实验解决，不凭多数投票。
6. 满足验玩门槛后仅交付成熟可玩HTML、完整来源/变更/验证说明。等待用户试玩反馈；即使三方都通过，也没有合并与发版权限。
