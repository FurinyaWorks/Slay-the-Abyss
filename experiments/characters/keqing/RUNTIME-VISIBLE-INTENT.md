# KQ041/058 visible-intent slice (HOLD)

The isolated adapter consults only `abyss_battle_intent_view.intentView`, the same public projection used by UI. Supported here: a single attack row with one hit and finite damage, or explicit buff/defend with no attack row. Hidden, unknown, multi-hit or multiple attack rows reject without paying. Hidden is never interpreted as zero or recovered from private Combat.intent. This deliberately partial bridge does not define final gameplay semantics when intentions are hidden; that remains a product decision.

Entry visible damage >0 enables041 block after its attack; zero enables058 second same-target hit. Actual Combat handles effects, payment, damage/status arithmetic; infusion is still the research wrapper's post-return update, NOT the formal paid dispatcher. Catalog restored and original input unchanged. No shared source edits.

Two tests include24 actual Jaw Worm public-view base/upgraded × buff/attack × infusion cases, insufficient-cost rollback and schema rejection. A real Run obtains Runic Dome and starts battle; poison Combat.intent confirms hidden projection never queries its numeric source. Separate mocked hidden/unknown faces verify adapter rejection without mutation, not encounter coverage. Controlled choice of the enemy's current move is a fixture, not natural AI/reward balance. Formal hidden-intent policy, full multi-hit intent support, reaction order, human/source/balance gates remain HOLD.

Review correction: every projected row must use a known attack/defend/buff/debuff icon and the list must be nonempty before any numeric decision. A buff containing an unsupported effect is rendered with an unknown row and is now rejected; a known attack plus an unknown row is likewise rejected, even when first-hit damage is numeric. Regression uses the real renderer for a mixed buff+unsupported-effect fixture and separate synthetic projected faces for missing/empty/unknown combinations. An initial overly narrow whitelist used `block` instead of the renderer's actual `defend` icon; targeted real-view tests caught it and the final whitelist uses `defend`.
