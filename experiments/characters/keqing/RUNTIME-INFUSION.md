# Finite infusion exchange adapter (HOLD)

Strict exports and an isolated actual Lua adapter add KQ021 and KQ022. KQ021 costs zero, clears all entry infusion and grants a single block amount of charges × 3/4; KQ022 costs two, replaces current infusion with one (never stacks) then grants 6/9 block. Both are true exhaust cards in the real Combat engine. The adapter validates the ORIGINAL resource state before overwriting anything, prepares the resource change on a private copy before block/exhaust resolution, executes real payment/effects and restores the canonical definition. Failed payment leaves the original untouched. Generic entry rejects the marker to avoid executing incomplete placeholders.

A zero-resource KQ021 still legitimately exhausts but grants no block. The engine forbids an empty effect list, so this branch uses its existing `draw 0` no-op rather than `block 0` (which could incorrectly benefit from Dexterity). Source `drawSourcePile` returns immediately for nonpositive count. Regression with Dexterity +10 verifies zero block remains zero. This is a limited adapter technique, not a newly registered no-op opcode or an assertion about arbitrary future draw-trigger plugins.

Two tests pass: strict malformed export rejection; actual Lua 12 combinations (two cards × two faces × entry infusion 0/1/2), real exhaust UID/no discard, three real following turns without card return, rejected repeat play, insufficient payment, malformed original NaN resource rejection, and an actual KQ003 recast followed by zero-cost KQ021 cashout. Initial failed empty-effect experiment was corrected; no production engine change was made.

Remaining gates: formal effect dispatch and exact setup/consume events, save/status display, integration with arbitrary Powers and card-internal reactions, natural reward acquisition, human/source/naming/balance. This is not a full 75-card runtime bridge. Shared lifecycle and the starter pure reducer API are unchanged; only the research wrapper exposes its existing resource validator and rejects the new marker. All existing HOLD limitations remain.
