# Conditional defense extension (HOLD)

The existing isolated conditional planner now admits KQ020/035/036/067: last entry infusion charge grants block after attack; living-enemy block capped at three; no-resource fallback block; and single-living-enemy fallback block. `conditionalCardProbe` is the descriptive alias of the existing exporter, whose earlier export remains compatible. Skill identity is preserved, so defensive skills do not spend infusion. Enemy counts use the actual runtime's `ActorPresence.isActive` predicate; dead fixtures are excluded.

Four targeted tests pass, retaining the earlier 36 actual Lua attack combinations and adding 32 new actual Lua cases across both faces, 1/2/4 live enemies plus a dead first enemy, infusion 0/1/2 and wedge absence/presence. Independent expected block/damage/payment/resource/expiry assertions cover the three-enemy cap, last-charge pre-card condition, single-enemy tradeoff and no-resource guard. Insufficient payment leaves input unchanged and canonical definitions are restored.

These conditions are planned from the entry snapshot for this declared subset. Ordinary block grants are not merged and therefore retain the real engine's separate grant semantics. Conditions after arbitrary block-trigger reactions that change living-enemy count/resources need formal action-time evaluation; those are NOT covered here. Half-dead/rebirth/escape special-encounter gameplay, formal reward acquisition, source naming, human approval, balance and production registration remain HOLD. Shared lifecycle and Combat/Actor are unchanged. This is not full 75-card integration.
