# Resource defense runtime adapter (HOLD)

Adds strict KQ006/007 single-source definition export and a separate isolated Lua adapter. It adds a fail-closed dispatch guard to the isolated starter wrapper; the pure lifecycle API, shared Combat/Actor and formal pools are untouched. KQ006 spends an existing wedge for extra block; KQ007 spends exactly one infusion charge. With no resource they still grant base block and do not fabricate a resource. They are skills and do not incur the attack-card infusion charge.

The adapter plans the current conditional effects on a copy, calls the actual Combat-backed starter wrapper for payment and block actions, restores the canonical definition and consumes the resource only after success. The two block effects remain separate ordinary block grants: each receives Dexterity/Frail independently. This is not the relic's fixed block and must not be fused into one modified grant. `runtime-defense.test.mjs` passes 2 tests, including 16 actual Lua face/resource/modifier combinations, insufficient energy with input unchanged, canonical definition restoration, and real KQ003 setup/recast sources before either resource spend.

The adapter is an explicit research entry, not a complete dispatcher. The generic wrapper rejects marked defense definitions with dedicated_defense_adapter_required. Only the defense adapter may compile the conditional block list and temporarily remove that marker on its private copy; it restores the original afterward. Formal integration must dispatch the resource contract rather than treat placeholder effects as complete. Pending choices, arbitrary power-trigger/reaction/death between the two block actions and exact intra-card resource event timing are not validated here. The reducer for the initial starter is intentionally unchanged and does not yet accept these defense-consumption events. No claim of full 75-card runtime coverage, balance, natural rewards, source naming or human approval. Existing gates remain HOLD.
