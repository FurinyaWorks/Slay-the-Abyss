## 目标和明确范围

以 **千星原生 UI 图片/底板/图标/官方场景/官方特效优先**，构建一份真实完整、可游玩的美术候选 GIL。自制图元仅用于图库无法表达且体验必要的部分。固定镜头 2.5D **已在 #553 做过**，不是新研究方向；如果能实质改善战斗场景，可在不迁移规则/手牌的条件下复用旧实验，但不得恢复 #556 全量 3D 迁移或再开整套框架。

重点场景顺序：
1. **先打通最难的真实战斗页**：至少 10 张合法动态手牌、真实一名玩家及双敌、费用/类型/稀有度/目标/状态/意图/能量/药水/遗物/伤害反馈、取消/点选/拖牌、胜利领奖回图。卡框、按钮、边框、费用球、面板、常用图标尽量用官方现成图片和模板；不要为复刻原 PNG 默认构建几千个矩形。
2. 以同一组件/主题方案完成 **菜单→选角→地图→战斗→事件/商店/奖励→两幕结算/重开**。保留现有同局业务流、动态文案、布局/触控安全区和可读性，禁止只交静态样品或借用社区默认皮肤替代整局。
3. **主角/敌人/背景** 优先检查已有官方图库和世界资产及 #553 经验证的能力；UI 造物头像不是全身动态立绘，不能混淆。必要时保留少量自绘资产，但必须记录必要性、控件数和加载风险。
4. **一次交付完整候选**：构建源、一个可导入 GIL、各主要页面同候选截图/短录屏、原生资源 ID/来源清单、性能与交互结果。禁止临时占位直接冒充最终品质。
