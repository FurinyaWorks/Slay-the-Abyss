# 红白黑主菜单实施计划

**目标：** 将本轮附件拟合为千星原生图元背景，以人物为中心，仅保留开始游戏、退出游戏；画质与加载一起验收。

**架构：** 复用既有分区轮廓提取、V25 三角转换与原生模板链路。最终仅装一档静态背景，控制每容器子项不超过60；不逐帧重建或逐块揭幕。按钮命中区固定，仅少量装饰连续过渡，不接触玩法状态和选角/祝福的在途成果。

**技术：** Python/Pillow/OpenCV/Shapely、Node 原生UI构建、Lua表现适配、现有Simulator SDK。

1. 保全原附件、固定SHA及develop基线；对红黑白块面、头部轮廓和眼睛分配拟合预算，比较400/800/1600/3200图元。诊断图只是离线检查，真实运行图另取。
2. 在菜单布局接入选定背景，去掉标题/占位选项，按钮置于左下安全区。浅暖白文字、小红色强调，不描金大字，不扩大hover命中区。
3. 先用真实Lua控制夹具复现突变；实现可中断、反向连续的短过渡，校验按下移出、禁用、切页/返回、结算恢复与触控命令。
4. 从本轮源码构建副本并读回；用既有适配器运行Simulator，查看真实画面，记录冷载、热返回、hover帧样本、往返控件与释放。不把软件截图时长称GPU FPS。
5. 定向回归、原生静态合同和独立复审；交付可试玩候选及证据。官方导入、ready与PC/实体手机未实测则保持未验证，不发布。

用户已明确：原图不能直接导入，要求自行拼素材/拟合；采用去标题双按钮方向。背景取舍以保人物面部、轮廓及颜色关系为先，不以单一误差分数代替看图。
