# TASK-100.1｜V25 原生组件加载与性能工程：根因、实验、机制

> 2026-11-09，Owner 授权登记的 M7 阻塞任务。基线 `develop@7821a7f44b518c09f6b565860e04e4823bc95153`；在途组件 PR [#565](https://github.com/FurinyaWorks/Slay-the-Abyss/pull/565) 的样本 HEAD `ae71692631e5a84c9716ea291dd1b32aa87281e0`。**本文件不是已经修复/真机验收的证明。**

## 一、问题的准确表述

现有玩家反馈：部分旧 2D 美术组件逐块出现，候选原生模板接入后看起来页面能更快完整呈现，但初始化和部分菜单更新成本上升。项目需要保留真正 V25 设计，而不是照搬社区皮肤或以删美术换性能。

**原理边界**：原生模板把复杂组件的组织和部分绘制配置放到构建期，减少 Lua 运行时逐零件创建/写属性；模板内部的子控件仍然存在，渲染并非零开销；预加载只改变时间安排。此前旧代码已经实例化基本图片控件，也有预制静态 UI；不要把“以前没用实例化”写成根因。

可核对的代码：
- `src/lua/abyss_traveler_portraits.lua`：旧角色 `begin→step` 的 `building/revealing`，逐项调用 `InstantiateClientUIControl` 和 setter；分批预算避免单次同步阻塞，可能导致渐进显示。
- `scripts/native-component-import.mjs`、`scripts/native-component-profile.mjs`：把源 GIA 视觉组件转换并映射到语义 UI；引入 `__kitOriginal`，保留游戏自有数据和输入。
- `src/lua/abyss_component_bridge.lua`：`M.new` 末尾 `attach(...binding.placements)` 在初始化阶段挂载全部 root placements；`placement()` 原生 `api.instantiate`。`nativeAt` 中的 `GetChildren()` 线性查找与 proxy `__index/__newindex` 可能引入运行时转发成本，但**目前只有疑点，没有证实该部分是菜单退步根因**。
- 产品视觉基准：`docs/design/APPROVED_UI_ADOPTION_20261105.md` 与私有 V25 原始设计（通过已保留的恢复入口查证）；`Enhanced` 简化版和外部组件默认视觉**不能替代 V25**。参考 `experiments/native-2d-vertical-slice/reference-handbook/`。

## 三、按假设诊断，先 RED 再修

| 假设 | 证据状态 | 最小受控实验 | 可用的修法 |
|---|---|---|---|
| H1：旧版部分美术在页面进入后逐图元创建、逐步 reveal | 代码直接支持；视觉边界待官方客户端记录 | 同一角色/相同视觉和显示数，录每阶段创建调用、完整可见时间与首次可点 | 构建期组件化、组件级挂载、先 hidden 准备好再一次 show |

| H3：代理路径查询/无效写入解释菜单 step 退步 | **未验证**；只能称嫌疑 | 按 API 分类计数 `__index/__newindex`、`GetChild/GetChildren`、`Set*`，对照缓存句柄、事件更新、同值跳过后的等价输出 | 对热点加有界句柄缓存，只有成功 setter 才承诺新状态；旧对象/重绑/销毁/false/throw 必须失效与重试 |
| H4：大量组件静态渲染/遮挡造成实际 GPU 帧卡 | **没有当前候选设备证据** | 保持同画质和同手牌/敌人数，记录官方 PC/Android 帧时和 GPU/内存（可访问时） | 需要真实帧时的证据再决定静态资源合并/减少过度绘制，不能先删掉 V25 关键视觉 |

## 四、长期机制（不是一次性补丁）

**构建期**：以 V25 设计为视觉规范，对元素分配原生模板/图层/文字绑定/交互状态；记录模板 ID、源指纹、子树规模及静态开销。组件原子挂载失败必须回滚，不得出现半完成页面。不得直接公开私有 V25/第三方完整资产。

**运行期：一个页面只有一个可观察状态机**：
```text
unprepared -> preparing (hidden) -> ready -> visible
                  |                  |
                failed             cached -> visible
                  |                  |
            cleanup/retry       released -> unprepared
```
- 多个页面由单个加载调度器控制准备预算，不在每次 OnUpdate 中无界创建。单个超大模板仍可能一次同步阻塞，必须记录组件粒度与单次挂载峰值。
- 业务层无需关心美术如何组装，仍读/写同一语义控件；loading、ready、show、hide、cancel、destroy 由组件层负责。页面等待期间是完整的过渡状态，不能暴露半张脸或半张卡。
- 句柄缓存按 UI 生命周期代次和原生对象身份绑定，失效、失败、销毁、回页、不同宿主不得复用旧引用；资源缓存有预算与明确所有者，既不无限常驻，也不每次重新创建。
- 动效只动必要的整体容器/属性，目标正确、可取消、无迟到回调；不允许因切场导致重复出牌、重复掉血、奖励重复领取。
- 对每屏定义可观测指标和预算，加入现有 UI/Host 相关测试与 PR 验证；预算先从真实当前基线推导，明确回归红线和可配置的观察阈值，不能单凭“组件数小于 N”宣布流畅。
