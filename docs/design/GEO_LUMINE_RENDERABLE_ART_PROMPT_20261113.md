## 1. 参考顺序：这三张最重要

1. **红色可莉选角页（第一优先）**：右边大人物、左边信息板、深红／橘红背景的大面积斜切色面；人物以**语义色区**（脸、头发、帽、衣服）的大多边形与有限阴影成型，眼睛等识别特征保留。学“构图和画法”，不复制可莉角色和具体 UI。
2. **蓝色派蒙祝福页**：深蓝色三角／多边形放射背景，中央偏上大角色，三条整齐选择项、顶栏 HUD 独立。学“主视觉与选项互不干扰”和“大色块舞台”。

## 2. 不可妥协的美术原则

- **拼大块而非拼像素**：优先大面积相接色块、明确人物剪影、每个主要材质的主色／亮部／暗部；避免全图均匀切碎或密集随机小三角。
- **高辨识度的稀疏细节**：只为双眼、嘴、白花、发型转折、服装白金分区与少数岩元素纹样保留细节；省图元不能先牺牲脸。
- **背景简、主体精**：背景用大面、少量远山或遗迹形状；角色有足够体积和自然表情；绝非无特征的小人或廉价占位。
- **固定分区 + 分层生产**：先划定主视觉、信息区、按钮与安全留白；背景／角色／装饰／交互底板／文字独立，不把动态文字、按钮状态与数值烘进背景图片。
- **官方原生素材优先**：可用的纸板、边框、按钮底材、场景和图标优先真实千星图库／场景资源，缺口才用少量低图元图形补充。**没有实际查到的资产 ID 不能虚构。**
- **避免视觉成本陷阱**：少用高频花纹、过度透明叠层、叠加高光、散碎岩晶、密集描线与光效；只用对构图和辨识有贡献的细节。
- **审美和可实现性是双门槛**：漂亮但需要极高图元代价不放行；好做但人物性格不对、造型丑也不放行。静态图元不更新也不意味着没有渲染成本。

## 3. 角色：女旅行者荧（Lumine），岩元素

**禁止误换成空／Aether。** 参考官方荧的白金旅行服、浅金色头发、白花发饰、琥珀眼睛、岩元素纹样；必须通过脸和服装本身认出荧，不靠乱撒岩晶当身份。

## 4. 可复制母提示词

> 请为《杀戮原塔2》生成一张面向《原神》千星奇域制作条件的高完成度**横屏 16:9 游戏 UI 视觉设计稿**。严格参考我上传的三张截图在“**大面积几何拼块、相邻明暗色面、固定构图、主体高辨识度、背景简化、独立 UI 层**”上的表达方法，但**不要直接照搬原角色、标志和具体文案**。
>
> **画面要从源头设计成容易拆解的大块面**，不要生成一张复杂插画再假设能用千百个小碎图元还原。大背景由少量连续几何色面组成；人物使用平涂多边形和清楚的阴影层次，但必须忠实保留脸、发饰、发型和服装结构；人物、背景、边框、装饰、文本区与按钮槽可被明确拆分。整个画面专业、清爽、有二次元气质，不廉价、不像随机三角形拼贴。
>
> **主角唯一是荧（Lumine，岩系女旅行者）**。保留浅金发、白色花发饰、琥珀眼、白金旅装、适量岩元素金色符号。她**温柔而沉着、坚定、自然、稍有探索好奇心**：放松的眉眼、轻微微笑／平静专注，微微侧身看向前方，绝非张嘴欢呼、朝观众伸手、幼态卖萌、怒目或冷酷。比例自然，不变成 Q 版或陌生少女。

> **布局必须为可玩的 UI 而非宣传海报**：角色占一个主区域，另留独立的文字、信息、按钮区域；要为手机触控与安全区预留空间。少量岩金或星形装饰即可，不要满屏岩晶、密集花纹、粒子和强光。文字在设计稿中只作为布局示意，正式数值、按钮和中文由现有原生游戏逻辑提供。
>
> **目标：不用牺牲画面审美，就能由已核实的千星官方素材、少量大图元、既有文字和按钮控件重建。** 输出完整视觉效果图，不输出代码、不在图片上写图元数量，也不要声称其已经可直接导入千星。后续将另做分层清单及实际复刻验证。

## 6. 给 Agent／Codex 的分层与落地检查

1. **设计先验**：按本规范和**实际上传的参考图**生一张，记录模型、原始提示词、候选、Owner 对画面与神态的结论。
2. **拆层表**：列清“官方原生模型/图库 ID（已验证才写）”“手工大面积图元”“人物重点区域”“原生按钮／文字”等。记录每层预估控件、变更频率、创建与销毁时机。**估算和实测分开**。
3. **先一屏 Spike**：优先小样复刻主菜单或选角，不扩成整套 UI。实际比较源稿、原生重建画面和角色脸的保真；不要为了数值像素误差继续堆碎图元。
4. **设备证据**：编译／GIA/GIL／官方导入与 ready／PC／实体手机分别留证；测首见、切页、操作响应、可读性、真实控件/容量、重复进出资源清理。美图不能证明已经不卡，离线运行不能替代真机。
5. **不改变正式交付边界**：不因新视觉方向擅自修改 [正式 UI 采用记录](APPROVED_UI_ADOPTION_20261105.md)、[当前 UI 规格](UI_DESIGN.md) 和 [背景决策](BACKGROUND_PROPOSAL.md)；按现有 Backlog 和 PR 合并机制组织实验，不私改规则或菜单功能。

**放行公式：视觉好 + 荧的人设对 + 能拆层复刻 + 真机可用，四项缺一不可。**
