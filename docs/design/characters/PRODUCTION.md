# 角色与卡牌生产

从这里开始设计新角色。本文与同目录文档是 Google Sheets 设计规范的整理迁移，不是新角色实现、数值变更或发行许可。迁移 PR 合并前按候选文档评审；合并后，本目录维护已迁移规则，Drive 对应范围只留历史，不双向编辑。来源、版本冲突与保留范围见 [迁移清单](MIGRATION.md)。

## 不变的产品边界

角色先有一个玩家能感知的核心战术取舍，再决定资源和卡牌。至少给出两种可达局面，证明最优选择会随局势变化；没有新选择的计数器和隐藏条件应删减。保留成熟单角色独立牌池底座；不借本次迁移加入元素反应大系统或多角色混牌。

当前成熟卡池规格为每角色 75 张；这是项目交付目标，不是数学最优值。先做最小可玩样板，再逐批填补战术缺口，不能把样板当完整交付，也不能为凑数放行不合格名字、同质牌或无用机制。早期“不预设75张”的探索记录不再覆盖后期生产规范。

## G0–G9：一条生产流程

| 阶段 | 交付与放行条件 |
| --- | --- |
| G0 角色合同 | 写核心取舍、玩家价值、人物身份与剧情时点、禁止项、当前环境；未批准的假设明确标出。 |
| G1 来源 | 必须先编制角色 P1/P2 官方锚点清单（技能、天赋、命座、TCG、战斗与日常语音、官方故事）；P3 真实文化为低优先级补充，P4 为原创兜底。逐卡记录准确来源及跳过高优先级的证据；缺项为 HOLD。 |
| G2 机制 | 定义状态、转换、触发时序、叠加、上限、退出和失败回滚；用相反局面验证真实取舍，画出资源来源到收益兑现的依赖。 |
| G3 小卡组 | 先明确职责，再核 P1→P4 来源、降级证据、**资料参考与面向玩家的名字是否分离**、N2/N3/N4/N6质量与独立审美审核。P3真实技法默认是动作资料，不是自动可用的卡名；未合格则留待命名/HOLD，同时检查经济依赖。 |
| G4 正确性 | 基础与升级分别验证费用、目标、效果顺序、状态持续、牌区、取消与异常；独立期望值不能直接照抄当前实现输出。 |
| G5 数值 | 走 B-GATE/C-GATE；提供同类 STS1 对照和实际机会成本。已有数值变更必须先有旧→新提案、可复现证据与用户批准。 |
| G6 构筑 | 分开报告理想成型与自然选牌；多策略、多遭遇、固定及保留种子，记录死抽、能否支付、失血、失败和主导套路。 |
| G7 试玩 | 资深玩家检验策略，新手检验理解；记录选择原因、关键误解、操作阻碍和主动重玩，不用机器人胜率替代乐趣。 |
| G8 扩容 | 核心循环通过后逐批补齐75张；每张新增牌重走来源、命名、机制、数值和体验关口。缺合格卡位时保留缺口。 |
| G9 冻结 | 同版本设计数据、文案、模拟输入、试玩及实现一致；审查、数值批准、回归和实际设备证据齐备。缺项不得称正式验收。 |

## R01–R16：检查面

| 规则 | 必查内容及失败边界 |
| --- | --- |
| R01 环境合同 | 明确初始牌、卡池、奖励、商店、恢复、遗物、遭遇、取整；逐项区分继承原版、有意改编与未实现，不能因同为3能量就当作相同环境。 |
| R02 结算合同 | 合法性→支付→结算区→有序效果→触发→死亡→牌区。预赠资源是否能支付本牌须显式定义；覆盖0/X费、取消、复制、目标死亡、满手与升级。 |
| R03 来源与兑现 | 获得组件→抽到→付得起→结算正确→及时兑现→连续生存。基础资源来源和额外产出分开；雷电每回合产愿不是通用角色默认。 |
| R04 实际成本 | 合算能量、抽牌机会、启动、生命/专属资源、延迟、消耗与后续收益，不设统一伤害价格表。 |
| R05 核心可及性 | 检验无来源、早抽/牌底、卡组变厚、满手、满资源等待和生命代价；保留只能解决已抽到后的保存，不解决未抽到。 |
| R06 状态与饱和 | 每个状态明示叠时间/强度/刷新/取高、次数与到期；检查0/1/2/100次和已饱和情境，不要求每次重复都赚钱。 |
| R07 铺垫与牌序 | 比较 A→B 与 B→A 的整条即时及后续收益；覆盖低血敌人、护甲、已有状态与下回合大伤，不追溯补算此前伤害。 |
| R08 增长与取整 | 固定按牌/命中/目标/实际失血的触发口径，以及加乘、取整、格挡、死亡顺序；覆盖多段、群体、致死±1和递归触发。 |
| R09 生命经济 | 联算防守密度、敌人意图、击杀减伤、恢复与升级机会及连续战失血；不能一遇死亡就给全部防御加值或增加固定回血。 |
| R10 单卡职责 | 奖励牌应有可达的值得拿和不拿情境；基础牌可以被替代，纯伤害可以有价值，不强迫每牌挂专属关键词。 |
| R11 自然成型 | 按正式奖励/商店/升级/移除节奏允许跳过，区分展示、拿到与成型；手工拼好的理想牌组不能替代自然获得证明。 |
| R12 循环与组合 | 查资源环、获取/启动代价、实际可达、反制与操作耗时。非终止程序和无代价套利必须拒绝；合法难成型强组合单独评审。 |
| R13 敌人与反制 | 覆盖真实支持的快攻、群怪、护甲、大伤、多段、负面/塞牌、成长和动作惩罚；缺少族群标未测，不要求各流派处处同胜率。 |
| R14 身份与可读性 | 来源、自然度、角色气质、效果不误导、全池区分分别审查；机械规则与风味分层，玩家在实际界面能取得必要信息。 |
| R15 仿真可信度 | 多策略、无未来信息泄漏、分离随机流与调参/保留种子；报告信息边界、置信区间、失败和截断，不把机器人当玩家。 |
| R16 单一规则源 | 结构化效果驱动卡文与模拟输入，名称出处和审批版本化；同版本摘要、独立断言和回归一致，不维护多份可写母表。 |

历史 E-GATE 的状态来源、3能量费用可达、负面状态实际存在、旗舰命名唯一与全流程证明，分别由 R02/R03/R04/R05/R10/R14 和 G4–G9 承接。历史 R-GATE 的状态时序、独立职责、支配、多段成长、高费价值和上线证据，由 R06–R10 及 BALANCE 承接。历史雷电专属修值不是通用准则。

## 新角色最小设计合同

直接在角色文档记录下列字段，不另造一套状态平台：

- 身份：稳定角色ID、人物/剧情时点、来源、当前设计版本、对应 Backlog、负责人及批准边界。
- 体验：一句话核心取舍、两种相反选择的可达局面、禁止项、最小样板目标与75卡扩容缺口。
- 环境与规则：初始条件、资源来源/消耗/上限、状态时序、奖励与敌人条件、未实现部分。
- 每张牌：稳定ID、职责、稀有度/渠道、基础与升级形式化效果、费用/目标/顺序，以及 P1–P4 来源级别、逐条原文位置、优先级降级证据与审核结果；风味独立于效果。
- 证据：失败反例、重放种子、对照卡、原/候选差异、审核者/日期/证据；分别记录正确性、设计证据、玩家体验，不用一个PASS包办。

默认状态为候选或未验证。只读档案中的历史PASS、模拟样本数和旧审批不能自动提升当前版本状态。

## 自动化的真实边界

`npm run validate:data`、`npm run build:data`、`npm run check:guidance` 和现有回归已经有工程入口，但覆盖以当前脚本实际读取的文件为准；新增候选并不会自动被这些命令认证。迁移只整理规则和导航，未新增命名、来源基线、B/C-GATE或构筑仿真CI。

后续接入机械检查时，要能拒绝代表性坏版本并接受合法样本，再接回正常生产路径。命名审美、人物表达、策略趣味和正式平衡仍需相应评审/试玩。源码正确、模拟完成、实机通过、发布批准必须分开报告。
