本轮接续 PR626，不复写第一轮 NO-GO，也不把它当作停止实验的理由。最新 develop 仍为 `3a061a76`，战斗 UI 依赖仍为 PR621 `680be9c5`。唯一视觉源和正式旧皮肤均未改。

## 开销来自哪里

首次显示主要受控件创建、初始化和完整发布阶段拖累。静态版仍有持续交互增量，预加载不能消除它。待机没有重建图片，但变换更新又显著放大拖动请求链路耗时；优化应同时减少静态图元和更新负担。

`render()`是CPU/驱动提交墙钟，pointer耗时包含浏览器、HTTP、worker排队与处理，不能分别冒充GPU时间或纯命中检测时间。上述对照定位到创建/发布、场景渲染提交与变换同步/交互链路三个层面；没有GPU timestamp或官方客户端profile，不把剩余成本武断归给某一个引擎函数。共享主机负载明显波动，后续以穿插旧版复测判断，不将跨轮低值当作确定收益。

## 预算怎样收敛

1. 复用原3439/133px和768混合图元证据，不重新拟合。新工作保持210×192画布。
2. 7303预算减半为3652 → 1826 → 913，每档独立GIL构建/读回、SDK、真实Simulator交互和截图。中点分割在低预算下产生明显脸部损失与衣裙横条。
3. 固定保留原图脸/花饰484个span，剩余图元按头发、轮廓、核心服饰加权分配。1369、1826、2739、3195、3652均保留实际结果，未用更高预算替换低预算截图。
4. 将30Hz改为批准动画的20次/2.2秒节奏，再将18个运动父容器减为4个。图片只创建一次；简化空间运动不是逐帧精确复播GIF。7303仅简化待机仍约116ms输入中位、固定拖动7次位置变更，单靠降低更新调用不足。
5. 取消矩形只能取中点的限制，沿原图像素边界选择最有收益的二分；同预算继续保留脸花。edge1826、edge2739和中点edge2283均实际验证。独审建议2283作为成本档、2739作为画质档，1826仍不作主候选。

原连续移动探针逐次await回执，48次事件的总时长受主机影响，不能只对比变更帧数。本轮追加48次目标60Hz可信CDP移动；分开记录发送完成、DOM合并后送达、真实跨度、请求和位置变更。首次旧版断言错误地要求DOM完整48条，45条时失败；原始失败保留，修正为确认48次发送完成并记录实际DOM数量，取消/3次攻击/能量与HP断言未改。

最后观测位置的绘制延迟不证明最终目标已呈现，`endpointVerified:false`。固定移动变更次数不是GPU FPS。原始记录、最终穿插复测和全表见 measurements.json、table.md、failures.json。

## 未来自绘怪物的预设边界

本轮仍只实现荧。`future-scene-budget.json`用本轮真实单体图片、拥有控件、setter数量，计算荧加2/3个同复杂度自绘怪物的总量；底层其他UI按13753存活控件保留，官方旧图作为回退也保留。它是算术规划，不是多角色压力测试、线性延迟估计或官方容量读数。

以2283档为例，3主体会是6849张原生图片，4主体为9132张，已经接近或超过本轮单荧7303的高成本量级。不能把“单荧可试”写成“此规格可直接给所有怪物复制”。未来还须按全场共享创建预算调度，不能将每controller的64调用/8ms创建切片简单乘给多个角色，宣称整场仍在8ms内。

研发预设应从**全场可见自绘图元总量约1500–2000**量级开始验证，而非每角色几千：3主体平均约500–670，4主体约375–500，再按主角和普通怪物的重要性分配。这是保守的待测目标，不是已验收安全上限，不修改现有可执行门槛。当前荧的可试画质需要约2.3k，已不能满足这个余量目标；完整多主体采用仍未放行。

若继续坚持批准稿的细节，后续技术准入需有可用的图片/材质或批量表示证据，或在更低总图元预算下证明画质与交互交集。原768混合方案已经失去细节，不能拿其计数直接当作可用生产规格。本轮不实施怪物、不降低批准稿要求，也不承诺未验证的原生纹理入口。
