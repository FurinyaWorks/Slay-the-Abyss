# 离线战役平衡抽样（M3现有引擎，非独立模拟器）

目的：复用真实 `Run`／`Nodes`／`Combat`、现有 `warrior75-autoplay-policy.lua` 和 `m3-normal-campaign.lua`，批量记录可复现战役结果。此工具**不会**调整卡牌数值、设置 HP、跳过真实抽牌或奖励；也不安装额外依赖。

## 运行

```bash
npm ci
npm run build:data
node scripts/balance-batch.mjs 42 5      # 5个种子、基线检查
node scripts/balance-batch.mjs 1000 100  # 100个种子，手动长跑
node --test tests/balance-batch.test.mjs
```

开始种子和数量为非负整数，单次1–200个种子；内部每批最多20个，沿用 `m3-normal-campaign.mjs` 原有边界。必须从**干净 Git 提交**运行，因为老战役入口要求完整来源身份。结果写 `build/balance-batch/report.json`，每批原始回放以压缩 JSON 单独留在 `build/balance-batch/batch-N/`，不污染被追踪的 `docs/evidence`。

## 指标与硬门禁

- 真实结果：胜利、战败、驾驶器阻断，胜率为**该固定策略在这些种子中的观测值**，不是玩家总体胜率。
- 对局统计：最终楼层和生命、出牌次数、领卡次数、所有行动中的净失血和恢复（按连续动作前后 HP 差量单独累计），中位数及原始逐局明细。
- **必须失败（退出非零）**：异常种子、重复种子、来源 SHA 变化、回放缺失或身份不符、无法复位、驾驶器阻断/脚本错误。
- **只报告，不自动拦截**：胜率、通关楼层、各卡选用、失血分布；没有校准过的目标阈值，不能随意给这些指标设“必须 > X%”。

## 证据边界与下一步

当前使用固定的 `warrior75-visible-state-v1` **铁甲战士策略**，真实战役从初始牌开始自然打牌、领奖和走节点，但尚未覆盖不同出牌代理及独立调参/保留随机种子；不能把它冒称多策略模拟、雷电V5 HTML的75卡测试、玩家手感、官方客户端或手机实机验收。

下一步再扩展防守／爆发／有限前瞻策略与各流派自然构筑，并记录展示率、选取率、触发率、坏牌占比及回合分布。现有数值不要由脚本直接自动修改：先锁定环境、设计实验，再提出可审查的数值提案。

**性能及CI成本**：这个入口只由明确的手工命令启动；`node --test` 的单元测试走 CI，**不会在每个 PR 都跑百局战役**。正式批量接入独立 CI 队列前，先量测10/20/100种子的真实耗时和内存。
