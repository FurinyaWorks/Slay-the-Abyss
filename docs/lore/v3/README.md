# Slay the Heavens · Lore v3（2026-11-14）

## 当前叙事边界

《原神》7.2 已公布的「判罚之钉」「圣土化」作为背景参照；不另造“深渊封印大事件”、正史高塔、天理的目的或结局。本作仍是拥有多角色的 Roguelike 卡牌游戏。地图层数、随机事件、商人、遗物与敌人是玩法结构，不能把《杀戮尖塔》原型怪物冒充《原神》官方角色。

- **运行时**：`data/presentation/narrative.zh-CN.json` → 现有 `build/lua/abyss_narrative.lua`。
- **批准快照**：`approved.zh-CN.json`；先经过文案评审才能一起改动它与运行时，禁止为了让测试通过而自动覆盖快照。
- **逐字段依据**：`SOURCES.json`，标注官方短引文、用户认可文字、Lore v2 保留文案、尚未接入的历史候选。
- **旧版归档**：`../v2/` 不改。旧的四段逐字保护是历史，不应迫使新版本继续讲封印故事。
- **显示位置**：旧开场电影已停用；新官方短句放进七天神像 / Neow 的既有引导页。Boss 不增加自编对白，失败不增加励志文案。两幕胜利继续显示「双幕挑战完成」与真实统计。
- **玩法边界**：不动数值、奖励、敌人 AI、RNG、事件选项、地图与结算机制。

## 永久文案工作流

1. 先确定**当前是否真的显示**：正式 Production / 开发入口 / 已停用面板 / 候选资料分别登记。
2. 每条修改明确来源：官方事实写版本和官方链接；人物口吻依据其具体行为与身份；原版《杀戮尖塔》只借场景和机制，不直接搬长对白。
3. **先删再写**：已有能用的句子原样保留；删除万能客服、虚构心理、空洞励志话和没有根据的神秘设定。不要为了统一风格而批量改机械效果描述。
4. 每个改动记录原文、新文、来源、用途、角色与结果是否一致，特别核对消耗金币、奖励、失败与禁用条件。
5. 评审通过后才更新 `approved.zh-CN.json` 和 `SOURCES.json`；`tests/lore-v3.test.mjs` 校验运行时与批准快照、来源登记、布局与旧故事回流。Lua/原生 UI 回归必须检查**玩家看到的字**，不能只检查 JSON。
6. 只有官方新剧情确实影响本作已有事实时，才创建新候选。官方没揭露的内容继续留白；活动结束不自动删掉合法的历史背景，也不把同人事件宣称为官方剧情。

本地 CI 成功不等于在千星原生导入、PC 和实体手机上完成验收。所有合并仍按仓库独立评审、完整 CI 和分支保护执行。
