## 发版执行纪律

版本号的正确顺序是：**合并功能 → 在发布分支升 2.0.0 并定稿 CHANGELOG → 用这些准确源码构建、运行质量/设备验收 → 发行 PR 合入 master → 确认源码树一致 → 打正式 Tag → 人工平台更新**。不要先验旧 `1.2.0` 游戏再偷偷改包成 `2.0.0` 而不重新构建；也不要用 Tag 代替发布回执。

验收证据至少记录：最终源码提交、构建标识、GIL SHA256、官方导入作品身份、PC/手机设备、截图或日志、官方容量报告、已知风险的 Go/No-Go 结论。任务状态仍只用 Backlog CLI 修改；本文件只勾有证据的发布关口。
