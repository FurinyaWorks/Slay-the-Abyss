# 目前要完成什么

**2026-11-13 起：以 M8 的产品体验与可玩角色为当前交付主线，M9 的内容扩展依赖明确的产品/容量准入。M7 工程专项已归档，不再设“优先把所有技术债优化完”的常驻任务池。**

自主 Agent 优先领取真实玩家缺陷、同候选官方/PC/手机验收、正式候选发布与已获 Owner 批准的角色切片。先查 Backlog、实际依赖、最新 develop、已认领工作和开放 PR，执行 `npm run task:pick -- TASK-编号`；HOLD 不另建平行任务。In Progress 的历史工程任务不能仅因“有事可做”自动继续。

**工程投入的触发条件**：有复现的产品问题、当前功能被具体架构风险卡住、质量/许可/容量硬门禁失败，或已有证据显示开发/CI 成本显著阻碍交付。解决该问题所需的最小架构切片跟随 M8/M9 的交付，修复后停止。不得为了单纯下降 CC、SCC、Fan-out 数字自发安排新的大范围重构。

日常沿用已合的质量棘轮、架构分层、来源与完整 CI 门禁；不放宽阈值，不删测试、不刷新旧基线或假装设备验收完成。未完成的工程历史 AC 仍保留在对应任务，未验项目不得标 Done。M7 的移交明细见 `docs/backlog-details/M7-PRODUCT-FIRST-HANDOFF-20261113.md`。

既有明确 Owner 批准规则仍适用：TASK-85/96/97、第三/四幕等任务不能因为任务搬迁自动获得新授权。近期发行不等待未来20/30角色容量实验；真正批量开放前须取得同候选容量 GO。
