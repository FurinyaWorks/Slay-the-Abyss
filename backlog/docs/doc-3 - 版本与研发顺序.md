# 版本与研发顺序

## 当前产品里程碑（2026-11-13）

1. **M8｜产品体验与核心特色（m-8）**：前两幕首局体验、UI、美术、手机/PC、稳定性、发版验收，以及首个明确批准的自研职业。由实际玩家价值决定顺序。
2. **M9｜内容建设与扩充（m-9）**：更多角色、怪物、第三幕与隐藏第四幕；内容量产必须满足已验证的容量、设备和复用能力，不阻塞近期发版。
3. **M7｜工程架构与性能强化（m-7）**：2026-11-13 退出活动里程碑，保留在历史归档。其已落地质量棘轮/CI/架构门禁成为每个功能 PR 的日常完成要求，未完成工程 AC 继续跟踪、按实际阻塞触发。

**不再执行“先做完 M7 才能开发产品”的阶段顺序，也没有 Sprint 日期自动放行/拒收。** 只核验现实依赖、具体 Owner 批准、现有工作所有权和验收证据。当前工作见[目前要完成什么](/documentation/2/)和 `docs/TASK_EXECUTION.md`。

当角色开发暴露具体重复逻辑、当容量阻碍 M9 增长、当 CI 稳定性阻碍交付时，在对应产品任务内用最小可验证工程改动解决。没有阻塞证据，不自发拆 CC/SCC 或建立“长期架构清零”独立任务。

旧 PR、已 Done 的工程切片、冻结数据、历史 M0–M6 及未完成 AC 不删除、不补勾。变更流程使用 Backlog CLI，CI 的 `verify:backlog` 和 Required Checks 必须仍通过。
