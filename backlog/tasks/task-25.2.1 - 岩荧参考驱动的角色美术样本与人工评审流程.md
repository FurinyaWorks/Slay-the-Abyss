## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
以岩元素旅行者**荧**（默认服装，不混入 2026 新装）做第一份可复用角色美术样本。采用成熟动画制作的 **参考板→造型探索→定稿角色设定表（model sheet）→动作设计→动画→游戏验收**；**Owner 不具备绘画、修图或动画制作技能，不承担任何手工修改。Owner 只需要看图、用自然语言指出哪里不对、选择方向并决定是否通过。AI/执行 Agent 负责从参考调查、生成、局部重画、修图、分层、拆帧、动画到工具操作及工程转换的全部实施，并负责把反馈翻译成可视修改。****先静态定稿，再使用 ChatGPT Images 2.6 生成 GIF；静态图未获准不得提前制作动画。** 出图后先由 AI 自检和独立视觉复核，再交 Owner 做审美决策，Owner 不应被迫替 AI 发现明显造型错误。

### 参考与来源（先看原图，不凭口头特征直接作画）
- **角色身份**：HoYoWiki 旅行者原立绘/游戏截图；对照脸、发型花饰、白金蓝衣装、轮廓、佩剑和岩元素特效，具体取舍由 Owner 看图确认。仅做非商业同人，保留来源与许可边界。
- **项目已批准的视觉方向**：私有 V25 与现有游戏战斗角色、头像槽规格；回查 TASK-25.2 与 PR #563 的 reference-handbook。
- **实现参考，不是身份参考**：私有 `STA-V25-reference-kit.zip`（SHA256 `74713d732fd7e557695a847bb596f605a6755e30300030f62cf9fc30006d7700`），含 `像素荧.gia`（SHA256 `e11d41d5e7409a4cf6799a0d1f1d4e8b6bd22e9dcfa4ff55121b9d4b773d2e2c`，192 个场景装饰部件）、动态可莉、低负载角色等；原始审计 `新增像素素材技术核验-20261108.md`。它们只能证明已有的结构/动作办法，不能证明手机性能。
- **动作草稿参考**：`traveler_geo_idle_spritesheet.png`（SHA256 `45ffdae00a10af169576c72b89adeca56d9422d148341a87cfb3aab8ddb35a18`），属内部候选，不冒充正式定稿或官方动画。

公共仓库仅保存引用、哈希、衍生决策和可公开结果；不上传私有Drive链接、第三方原包/贴图。每轮在**同一份简短记录**里关联「参考来源/版本或SHA→具体特征→候选/变更理由→Owner通过/驳回→产物SHA」，不新建庞大表单。

### 交付人审之前的自动视觉质检（Visual QA / Gate 0）

直接**复用** `docs/art/CARD_ILLUSTRATION_STANDARD.md` 已有的「源图自检、独立复核、身份与画面关系对照」，将其应用于旅行者**每一张静态候选和 GIF 的关键帧**。不另建大型美术管理系统。

1. **生成者自检**：看完整图、手脸/持剑处局部放大图、游戏中实际 1× 显示尺寸；与已选参考对照，不只看生成大图是否“好看”。
2. **另一名视觉审查 Agent 独立复核**（不能只让生成者重复夸赞自己的结果）：逐项检查人体解剖与透视（手指/拇指数量和遮挡逻辑、手腕、关节、肢体连接）、手与剑柄接触及武器结构、脸/眼/发饰和角色特征、衣装/左右关系、透明边缘及 1× 可读性。**不要求每根手指都露出**，但可见数量与遮挡必须合乎解剖；不允许畸指、粘指、悬空剑柄、多余肢体或左右结构跳变。检查不确定时记 `UNKNOWN`，不伪称通过。
3. **失败先自动修**：发现 FAIL/UNKNOWN 时，针对问题局部重绘并保留其余已通过区域；修复两轮仍不稳，**主动简化姿势**，如握拳、手背朝向观众、手被剑柄或衣袖合理遮挡，减少暴露手指，不靠硬加一根手指或遮住关键身份特征蒙混。可见手与武器的连接仍须准确。
4. **交付门禁**：每轮只留一条简短的可机读审查记录：输入图 SHA、角色参考 ID、视图/尺寸、检查项 PASS/FAIL/UNKNOWN 与局部截图、修复说明、复审结果、输出 SHA。只有**生成者自检通过 + 独立视觉复核通过**的版本可送 Owner 评审；Owner 评价转为下一轮的明确回归检查项。独立视觉复核是尽量自动化的 **AI 评审，不是已证实的几何识别算法**；它可能漏检，Owner 最终审美批准仍不可自动代签。

**本轮已知失败样本**：2026-11-10 的像素版荧候选 PNG（1086×1448，SHA256 `0b329362a5d3fae984b42b10d429874ba08cd0526677fd6cb782ac8670324a30`，私有图片不提交公共仓库），非持剑侧张开的手被 Owner 指出可见手指异常（似乎仅有四指、缺合理遮挡）。标记为 **FAIL / 需修改**，不得算“已定稿”或喂给 Images 2.6 生产正式动画；先改成更易准确表达的收拢/半握拳或自然遮挡姿势，并以同视角局部对照复审。

### 轻量工业制作流程（严禁倒序）
1. **Design Brief 与参考板**：确定首个交付用途（战斗区朝右持剑的全身角色、真实屏幕显示尺寸）、风格与关键识别点。官方形象参考、旧 V25、千星实现样例分开标注。AI 用具体对照图解释关键特征并给出有限选项；Owner 只需用自然语言评价，不要求画草图、整理素材或填写专业参数。
2. **静态造型探索**：先做 2–3 个低成本轮廓/比例缩略稿；Owner 看图选方向或提出意见，由 AI 修改并精修成 1 张同尺寸的完整彩色静态角色；不把 Krita、Aseprite、Photoshop 等编辑操作交给 Owner。按实际战斗画面 1× 展示，优先检查角色是否认得出、姿态和服装是否协调，不盲追原 PNG 像素误差。每个准备交给 Owner 的候选必须先通过上述 Gate 0；不把明显畸形或无解遮挡交给 Owner 筛错。
3. **Model Sheet 定稿关口 A（必须由 Owner 批准）**：冻结正式战斗 3/4 视角静态图、必要的正/侧结构辅助、头脸和服饰锚点、配色与剑的位置；保存原图、版本/哈希和通过理由。未批准时由 AI 按反馈自行修复，提供修改前后对照，Owner 只负责复核；禁止要求 Owner 绘画、并行批量衍生和启动动画。
4. **千星静态可实现性关口 B**：用现有原生图片、低图元/场景元件做**单角色静态竖切**，对照定稿图记录可见画质、控件数和初次完整显示；若现有平台接口无法承载这种画质，先调静态制作路线，**不浪费成本制作动画**。复用已有 #553、#582、#588 和 TASK-94，不再造新导出器。
5. **动作设计→Images 2.6 GIF**：在 A/B 均获认可后，以冻结的同一张静态主图和 model sheet 作为唯一角色身份依据；先设计简短待机动作节奏与关键姿势，再生成可循环待机 GIF，经人审后再做**攻击（起手/命中/收招）**。每段保留提示词、输入静态图 SHA、GIF 与逐帧结果；每个关键姿势及异常疑似帧复用 Gate 0，检查发饰、五官、衣装、手指/握持、武器、视角、首尾连续性及身份漂移，未通过不交 Owner 审核。AI 动图可能漂移，逐帧修复由 AI/执行 Agent 完成，Owner 仅审核视觉，不以 GIF 能播放冒充合格。
6. **转换与验收关口 C**：GIF 仅是动画原型，不能当作千星可直接导入的纹理。拆帧或提取关键姿势，**优先复用**现有原生帧组/显隐/Tween 方法，制作待机与攻击的真实 GIL 候选；人工看真实游戏中的静/动态一致性，再按已有门禁分别验证 SDK、官方 PC 和实体手机的画面、输入、加载与性能。未验则保留 UNVERIFIED，绝不默认发版。

只有荧一个角色通过 A→B→C，才抽取极简「参考→静态→动画→原生适配→审核」配方供怪物/其他角色复用；其余角色、卡图量产不在本次范围内。

### 2026-11-10｜修正规格：等价迁移《杀戮尖塔》一代骨骼动画机制

**已核查的原作事实：**
- [BaseMod 动画教程](https://github-wiki-see.page/m/daviscook477/BaseMod/wiki/Custom-Character-Animations)：StS1 使用 Spine 骨骼动画；动画按 30fps 制作，原点放在地面；**不是每帧重画整个人物 PNG**。
- [StS1 官方 Weekly Patch 47](https://store.steampowered.com/news/posts/?appids=646570&enddate=1542327142)：实有 Ironclad 的待机/受击更新、Silent 待机速度微调，以及三职业受击→待机 0.1 秒过渡。**原待机曲线、幅度、完整关键帧和精确循环长度并没有取得**；不能虚构为 8 帧或 1.84 秒。
- 千星未证实能运行 Spine 资源；要迁移**分件、关键帧插值、状态机、过渡机制**，不承诺直接读入 .skel/.atlas、也不复制原作贴图。

**等价移植到本项目（使用现有图元、父容器和 Tween；保留旅行者已批准的整幅构图）**
1. 将实际原生对象按 **双脚/腿、躯干、头/头发、背后飘带、裙摆、剑/握柄** 组织为少数可独立运动的部件。双脚落点不变、持剑连接不变，角色朝向/服装/面孔不随帧改变。**不重画整张图、不要让每个矩形独立随帧抖动。**
2. **idle 循环、attack 单次、hit 单次、dead 终止**，攻击/受击完成回待机；hit→idle 优先实测原版确有的 0.1 秒混合，attack→idle 保留待测参数，不编造官方数值。真实伤害和回合仍以 Combat 为唯一事务源。
3. 待机通过连续时间插值少数关键姿势：身体呼吸、头发/飘带延迟跟随。30fps 是**原作制作时间轴**不是本项目设备FPS上限。可见性必须按真实游戏显示尺寸验：既不能像 v1 几乎不动，也不能全身漂移或局部闪烁。首尾衔接、遮挡、头脸、手和武器必须通过 Gate 0。
4. 切换动画、打断、取消、换场时取消旧 Tween 和迟到回调并恢复正确 pose。真实图元数（57仅为低资源实验目标，不是已证实上限）、每步原生写入、加载/完整显现、PC/手机帧时要独立核算。
5. **最小验收**：先在复用的生产人物宿主上完成 idle→attack→idle 与 idle→hit→idle 及中断取消的可见回放，再实测 GIL、官方客户端、目标手机。只生成 GIF 不算原生落地。

**历史失败及本轮独立原型：**
- v1 是 8 帧×230ms 最大仅 3.51 原图像素变化，缩半尺寸后不足 2 像素，Owner 看来完全没动：**FAIL**，否决其“StS 原版待机复刻”口径。
- v2 使用**同一静态图像**（SHA256 32830a9ab3f0b181202205bba59447efe660ce3225ab26f32943c54753a105de）做可重复的分区域光学变形；16帧×110ms，脚底输出最后65px逐帧相同，半周期像素差记录在会话产物 lumine_idle_rig_motion_v2_qa.json；GIF 是 lumine_idle_rig_motion_v2.gif。**这只是可见动作与锚点试验，不是原版 Spine 骨骼，不是千星实际图元动画，不是57图元证明，也没有正式视觉验收**。正式实现须使用可独立运动的原生分组，不能把位图光学变形直接算作原生资源。
- 原已知手指畸形缺陷仍为 Gate 0 失败例；由 AI/执行 Agent 修复，Owner只看效果。
